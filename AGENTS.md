Guide for coding agents working on this portfolio site. Read it fully before editing.

## What this project is

The university-admissions portfolio of Muhammadumar Muhammadtoirov (public name Muhammadumar Toirov), a high-school student from Margilan, Uzbekistan interested in AI, computer science, education and research. It is a single static page, `index.html`, with two "eras" on computers and one phone version:

1. **1996 desktop**: a retro OS called **UmarOS 95** with a boot screen, desktop icons, draggable/resizable windows, taskbar, Start menu, mini-apps (Minesweeper, Paint, Chat), screensaver, joke crash screen and a helper character, Disky. The owner appears on the right as a dithered school portrait (`img/me-1996.png`, `ME.photo96`, 240×304 with a 96-colour palette, shown at its real size in a bevelled frame, `#me96`; regenerate it with the retro script rather than scaling it up) with his name in pixel type; Display Properties can hide it (`store` key `me96`). 1996 apps also include **Gallery** (`C:Gallery`: one folder per album from `ALBUMS()`, thumbnails, Backspace/Back), **Imaging** (one reused viewer window, `openPhoto96(album, photo)`, Previous/Next/arrow keys), a **DOS Prompt** (`initDos`: HELP, WHOAMI, DIR, OPEN name, HONORS, SKILLS, RESEARCH, GALLERY, CONTACT, VER, DATE, CLS, WIN2026, EXIT; never call it MS-DOS) and **How I think.txt** (principles + what didn't work). About Me.txt includes the journey.
2. **2026 desktop**: the "update" installs **UmarOS 2026** (`#os26`), rebuilt from scratch in the style of today's desktop operating systems (the owner asked for a Windows-like look; original artwork and the UmarOS name/logo only, never Microsoft/Windows names or logos). The default wallpaper is **Blue silk** (`img/wallpaper-silk.webp`), an original abstract wallpaper in the style of today's desktops (flowing blue ribbons, glow on the right), generated by a script (sharp + SVG, run outside the project); regenerate rather than edit it. The drawn **thinking board** (`img/wallpaper-2026.webp`, every phrase from `ME`) and the other wallpapers are in Settings → Personalization. **On the right of the desktop, centred, is the owner** (`.wself`), like an account picture on a sign-in screen: his background-removed photo (`img/me-2026.webp`) in a glass circle (head and shoulders rise out of it, the circle clips the waist), then `ME.publicName`, `ME.role` and `ME.location`. It takes the right 38% of the screen; windows open at their normal size centred right of the icons and may cover it, like a real desktop. An "About this picture" button top-right describes the current wallpaper (`about` on each wallpaper). Desktop icons sit in columns on the left (Recycle Bin, About Me, Projects folder, Research.pdf, Resume.pdf, Notes, Gallery folder, Mail, Terminal, GitHub; shortcuts carry an arrow badge; double-click to open, one tap on phones). The look follows today's Windows-style desktops closely (the owner asked for "Windows 11 Pro"): Windows-blue accent (`--acc` #4cc2ff on dark surfaces, `--accd` #005fb8 on light ones; no lime inside `#os26`), an original blue "U" Start glyph (`ART.logo`, never the four-pane logo), Segoe UI Variable. The dark taskbar has a **"Get to know me"** widget on the left (a progress ring `.wring` with `#wBadge` and "n of 5 steps done"; opens the widgets board with the five-step tour, Now, Research, Honors and the photo), then centred Start, a search box, pinned apps (Files, About Me, Research.pdf, Notes, Mail, Terminal, Browser, Settings) plus any other running windows, and on the right ^, ENG, the network/volume/battery button (opens **Quick settings**: decorative toggles and sliders, flyout `qs`), a clock (opens the **notification center** above the calendar, flyout `cal` with `.wnc` + `.wcalb`) and a show-desktop sliver. Right-clicking the desktop opens a **context menu** (flyout `ctx`: Refresh, Personalize, Display settings, Open in Terminal, Get to know me, Read as a web page). The Start menu has Pinned apps, Recommended (the five steps with app icons, "Step n" or "Done" plus a tick, and Resume.pdf) and a footer with the owner's photo and name and icon buttons for Settings, Files and Power (Go back to UmarOS 95, Read as a web page). Files shows its folder as a tab in the title bar (`tabs: true` on the app) and has a disabled New button like a real explorer. Light app windows have the app icon + title on the left and minimize / maximize / close on the right; drag the title bar (drop at the top edge to maximize), resize from the corner. Apps: **About Me** (settings-style: profile card, Home, My story, Journey, Activities, Honors & skills), **Files** (explorer-style: Home/Projects/Documents/Gallery, back/forward/up, address bar, folder search, Large icons/Details views, details pane, status bar; opening a project opens its case study as `<title>.doc`), **Research.pdf** (document viewer with zoom and the scenario rater), **Notes** (notepad with one tab per note: How I think, What didn't work, Now, Lab entries), **Mail**, **Terminal**, **Browser** (shows `#web`), **Settings** (About this site, Personalization: wallpaper + "Show me on the desktop", Recovery: go back to 1996), **Photos** and **Recycle Bin**. Entering 2026 opens no window: the visitor sees a clean desktop with his photo and name, plus a one-time welcome notification pointing to "Get to know me".
3. **Phone (UmarOS Mobile)**: on phones this is the **only** version (the owner asked for "just a phone, like an iPhone 17"). A tiny `<script id="phoneCheck">` in `<head>` adds `html.phone` before the first paint when the screen is ≤700px wide or a touch screen with a short side under 600px (never inside the 2026 Browser app's `#web` frame); CSS then hides every other body child and the start-up code calls `buildPhone()` instead of booting 1996. It is an original design in the style of today's phones (no Apple names, logos, fake status bar or camera notch; the real phone shows its own): a **lock screen** (date, big clock, name widget, the owner's cutout, a welcome notification; tap or swipe up to open), a **home screen** (profile widget → About Me, "Get to know me" widget with the five steps ticking off as they're visited, app icons, Search pill, dock) and full-screen **apps**: About Me, Projects (list → project with photos and links), Research, Photos (albums → grid → viewer with swipe), Notes, Journey, Awards, Mail (mailto), Settings (wallpaper, about this site), Search; Resume, GitHub and LinkedIn open their links. Screens stack (`pPush`/`pPop`) and follow browser history, so the phone's back gesture works. Code: `PG` glyphs, `PAPPS`, `PGRID`, `PDOCK`, `PSTEPS`, `p*()` screens, `buildPhone`; CSS under `#phone` with `p`-prefixed classes. Everything reads `ME`.
4. **Web-page view**: the same content as one scrolling page (`#modern`: big type, scroll reveals, case-study drawer, light "paper" research section), opened from "Read as a web page" in the dock or top bar, or directly via `#web`. It sits above the 2026 desktop and has a "Back to desktop" button.

**Every visit starts in 1996.** Visitors reach 2026 only through the in-desktop update (time-travel animation). Entering 2026 does not change the address, so a reload goes back to the 1996 boot. Explicit share links still exist: `#2026` (desktop) and `#web` (web page).

The retro desktop is the hook; the 2026 desktop and web page are the substance. The site must pass the "30-second test": a reader should quickly learn who he is, what he cares about, what he has built and researched, how it connects, and what's next.

The concept is inspired by robbyyeager.com. **All code, text and graphics here are original.** See "Hard rules".

## Hard rules

- **Do not copy from robbyyeager.com** or any other site: no source code, CSS, copy/text, images, logos or audio.
- **No third-party characters or trademarks.** The helper is an original floppy-disk character ("Disky"), drawn as inline SVG. Never Clippy or any other mascot. No Microsoft/Windows logos or product names; the OS is "UmarOS" (`ME.osName`).
- **Never fabricate.** No invented achievements, statistics, users, awards, dates, quotes or impact. If something is unverified, leave the field empty (render functions hide empty fields) and list it in the `CONTENT_TO_VERIFY` comment at the top of the script. No SAT score unless the owner supplies the final official one.
- **Voice:** a high-school student. "I built / I tested / I noticed / I'm exploring", not corporate or adult-professional. Avoid "passionate", "innovative", "revolutionary", "cutting-edge", "world-class". Aspirations are framed as aspirations.
- **Keep it a single self-contained file** unless the owner asks otherwise. No build step, no framework, no npm dependencies. Only external requests: Google Fonts (VT323, Pixelify Sans, Inter, Archivo).
- **Content lives in the `ME` config object only.** Exception: the static SEO parts, because crawlers and link previews don't run JS: the `<head>` tags (title, description, canonical, Open Graph, Twitter), the JSON-LD `ProfilePage`/`Person` block, and the `<noscript>` summary at the top of `<body>`. They lead with the full name **Muhammadumar Muhammadtoirov** (what people search for), with "Muhammadumar Toirov" as the alternate name. Keep them in sync with `ME` (`name`, `publicName`, `seoTitle`, `siteUrl`, `links`, roles). If the domain changes, update `canonical`, `og:url`, `og:image`, the JSON-LD URLs, `robots.txt` and `sitemap.xml` together.
- **Escape all config text** with `esc()` (or `acc()`, which escapes and turns `*word*` into an accent) when interpolating into HTML.
- **Wrap browser storage** through `store.get` / `store.set`.
- Film references are banned in the warp: keep 142 MPH and 3.60 GW, captions "Spinning up the timeline…", gauges SPEED / POWER.

## How to do common tasks

**Change content:** edit `ME` only. Both eras read from it.

**Projects = the Common App activity list (proof site).** `ME.projects` mirrors the owner's Common App activities in the same order, with the same roles, hours and numbers. Each can carry `category`, `commitment` (hours), `cover` (card photo), `gallery: [{ src, cap }]` (proof photos in `img/proof/`, made from the owner's own files) and `links` (live proof). Galleries appear in every case study (desktop, web drawer, 1996), in the **Gallery** (desktop folder → Files `gallery`, one subfolder per album at location `al:<i>`, photos open in Photos at that photo; plus the `#m-gallery` section of the web page) and as albums in the Photos app. All of these read `ALBUMS()` (projects with galleries, then `ME.albums`, which holds extra albums such as the olympiad certificates). `ME.research` mirrors the accepted paper (final numbers, `figures`). Never publish other people's personal data: blur certificates and IDs. If an activity changes on the Common App, change it here too.

**Add a project:** append to `ME.projects` with a unique `id`, `icon` (1996 emoji), `mark` (short text shown large on the 2026 card), `title`, `tagline`, `status`, `year`, `role`, `tech[]`, `keys[]` (chat-bot keywords), `image`, `card: {problem, build, evidence}`, the case-study fields `problem, question, hypothesis, build, experiment, result, reflection, next`, and `links[]`. All are optional except `id`/`title`/`card`; empty ones are hidden. `anchor: "m-..."` makes the card scroll to a section instead of opening a drawer (used by the research card). The first project is the wide featured card.

**Add a desktop window/app:**
1. Add to `APPS`: `key: { icon, title, label?, w, h, desk?, render: () => "<html>" }`. `desk: true` adds a desktop icon. An entry with `url` instead of `render` opens that link in a new tab (used by GitHub).
2. `render` output usually starts with `.menubar` (optional) and a `.body` element (`.body.pad`, `.body.in`).
3. Behaviour goes in `INIT.key = el => {...}`. Query inside `el`, not `document`.
4. Add `["key", "icon", "Label"]` to `START` to list it in the Start menu.
5. Any element with `data-open="key"` opens that app. `data-jump="m-section"` on a 1996 element time-travels and lands on that 2026 section.

**Add a system action:** add the key to the list at the top of `openApp` and handle it in `system()`.

**Add a 2026 app:** first ask whether it fits inside an existing app (a page in About Me, a note in Notes, a folder in Files); keep the taskbar readable and the tour at five steps. Otherwise write `fooApp()` (and `initFoo(el, opts)`) rendering from `ME` with `esc()`, add it to `APPS26` (it appears in Start → Pinned automatically; add artwork to `ART`), and add the key to `PINNED` to pin it to the taskbar. Style it under `#os26` with `w`-prefixed classes. If it should also be on the web page, add a section in `buildModern()`.

**Change the desktop photo:** replace the files in `img/` (keep the names) or point `ME.desktop` at new ones. The cutout must be the owner's own photo with a transparent background; the wallpaper should be a scene he took or his own photo.

**Commands:** on the desktop, `data-os="key"` on any element runs `osCmd`: an app key opens that app, `webfull` opens the full-screen web page, `search` opens search, `back96` returns to 1996. `data-fl="start|search|widgets|cal|qs|pic"` toggles a flyout. In 1996, `data-jump="key"` time-travels and opens that desktop app.

## Behaviour details worth knowing

- **Phones:** see "Phone (UmarOS Mobile)" above; the rules below only apply to narrow desktop windows that load before the phone check, i.e. never in practice. Keep them working anyway.
- **Mobile (≤700px):** 1996 and 2026 windows go full-screen with no drag/resize; 1996 icons and 2026 desktop icons/files open on one tap; Disky, the tray icons and the show-desktop sliver are hidden; the 2026 desktop icons become a grid at the top with the owner's photo below; the taskbar scrolls sideways. Web page (≤860px): single column and a Menu button.
- **Reduced motion:** no auto screensaver, warp skipped, no window/flyout/toast animations, no reveals or hero word animation, no drawer slide.
- **Keyboard:** Enter opens icons, files and menu items; arrow keys move through the 1996 Start menu, About Me pages, Files items and search results; Backspace goes back in Files; Ctrl/Cmd+K opens search; Escape closes the open flyout (focus returns to its button), the focused window, the case drawer or the mobile nav. Inert layering: the 1996 desktop is `inert` while 2026 shows, `#os26` is `inert` under the full-screen web page, and the web page is `inert` behind its drawer.
- **Persistence (`store`):** `noWelcome`, `wall` (1996 wallpaper), `wall26n` (2026 wallpaper, stored by name so reordering the list is safe), `me26` (show the owner's photo on the 2026 desktop), `me96` (the same on the 1996 desktop), `wallP` (phone wallpaper, by name). Nothing remembers the era: every visit starts in 1996 on purpose.
- **Easter eggs:** clicking the clock 7 times shows the joke crash screen; 90 s idle starts the starfield.
- **Research scenario rater** is local only: nothing is stored or sent. It shows the qualitative early pattern from `research.patternText`, never numbers.
- **Contact** uses `mailto:` only. A real form backend (e.g. Formspree) must be discussed with the owner first.

## Testing

There is no test suite. Before finishing any change:

1. **Syntax check:**
   ```bash
   node -e "const h=require('fs').readFileSync('index.html','utf8');new Function(h.split('<script>')[1].split('</script>')[0]);console.log('SYNTAX_OK')"
   ```
2. **Screenshot both eras** with headless Edge (save in a scratch folder, not the project):
   ```bash
   EDGE="/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"
   "$EDGE" --headless=new --disable-gpu --hide-scrollbars --window-size=1400,900 --virtual-time-budget=12000 --screenshot="$TMP/1996.png" "file:///C:/Users/Muhammadumar/portfolio/index.html"
   "$EDGE" --headless=new --disable-gpu --hide-scrollbars --window-size=1400,900 --virtual-time-budget=5000  --screenshot="$TMP/2026.png" "file:///C:/Users/Muhammadumar/portfolio/index.html#2026"
   ```
3. **Pitfalls:**
   - To see other desktop windows, inject a script into a scratch copy that calls `osOpen("files")`, `osProject("ilmhub")`, `osOpen("notes", { note: "fail" })`, `osOpen("about", { page: "journey" })`, `toggleFly("start")`, `openWeb()` etc. A scratch copy outside the project must rewrite `img/` paths to absolute `file:///` URLs, or the photos won't load.
   - Headless Edge reports a smaller viewport height at load than it renders; desktop windows therefore use CSS `min()` heights, not `innerHeight`.
   - Headless Edge won't render narrower than about 500px. For phone width, screenshot a scratch page containing `<iframe style="width:402px;height:874px">` (iPhone 17) pointing at the site: a narrow frame shows the **phone** version. Call `pUnlock()`, `pOpenApp("projects")`, `pProject("ilmhub")`, `pViewer(album, photo)` etc. from an injected script to reach screens. To check the desktops at narrow widths you would have to remove `html.phone`, which real phones never do.
   - `#modern` scrolls internally, so a tall window won't show lower sections. Make a scratch copy that injects a script (after load) to add `seen` to all `.rv` elements and set `#modern`'s `scrollTop`, plus `*{transition:none!important;animation:none!important}`. Insert it before the **last** `</body>`.
   - `--force-prefers-reduced-motion` tests reduced motion.
   - Never leave test injections in `index.html`.
4. Check 390×844, 768×1024, 1366×768 and 1440×900 when touching layout.

## Style conventions

- Plain ES2020+ JS, no modules, 2-space indent, template-literal rendering.
- Desktop UI uses bevel classes and the Tahoma/`--ui` stack; no modern styling on the 1996 side, no retro styling in `#modern`.
- Accessibility basics: buttons for clickable things, `aria-label` on icon-only buttons, Enter/Space on custom controls, visible focus.
